# Paste Guard

화면 캡처를 붙여넣는 순간, 그 안의 개인정보·보안 정보(이메일, 전화번호, API 키, 학생 이름 등)를 찾아 가려 주는 크롬 확장이다. 사용자가 점검을 따로 떠올리지 않아도, 붙여넣기가 일어나면 먼저 확인 화면이 뜬다.

```
Ctrl+V ─▶ 확장이 붙여넣기를 막음 ─▶ 점검 서버
                                     ├ OCR: 글자와 글자별 위치
                                     ├ 규칙: 이메일·전화·키·토큰·주소 형식
                                     └ LLM(선택): 예시 값 거르기, 규칙이 놓친 이름·알림 내용 찾기
          ◀── 후보가 미리 선택된 확인 화면 ◀──┘
확인 ─▶ 고른 영역을 검게 칠한 이미지로 다시 붙여넣기 (클립보드도 가린 이미지로 바뀜)
```

후보가 하나도 없으면 확인 화면 없이 원본이 그대로 붙여넣어진다.

## 써 보기

준비물: [uv](https://docs.astral.sh/uv/)(파이썬 패키지 관리자), 크롬.

**1. 점검 서버 실행**

```bash
cd server
uv run python -m uvicorn main:app --port 8787
```

처음 실행하면 의존성 설치와 OCR 모델 내려받기에 몇 분이 걸린다.

**2. 확장 없이 데모 페이지에서 보기**

http://localhost:8787 을 연다. 샘플 버튼을 누르거나, 아무 화면 캡처나 복사해 입력창에 `Ctrl+V` 하면 된다. 이 페이지에는 확장과 같은 스크립트가 들어 있어서, 확장을 깔지 않아도 동작한다.

**3. 확장 설치 후 실제 사이트에서 보기**

1. 크롬에서 `chrome://extensions`를 연다
2. 오른쪽 위 「개발자 모드」를 켠다
3. 「압축해제된 확장 프로그램을 로드합니다」를 누르고 `extension` 폴더를 고른다
4. 아무 웹 서비스의 입력창에 화면 캡처를 붙여넣는다

서버를 다른 곳(대회 GPU 서버 등)에서 돌리면, 확장 아이콘을 눌러 서버 주소를 바꾼다.

## AI 문맥 판정 켜기

OpenAI 호환 API라면 무엇이든 연결된다(L4 서버의 vLLM, Ollama, 외부 API). 환경변수를 주고 서버를 띄운다.

```bash
LLM_BASE_URL=http://<GPU서버>:8000/v1 LLM_MODEL=<모델 이름> uv run python -m uvicorn main:app --port 8787
```

외부 API를 쓰려면 `LLM_API_KEY`도 준다. 판정 결과는 확인 화면의 목록에 「AI」로 표시된다. LLM 호출이 실패해도 규칙 후보만으로 계속 동작한다.

## 파일

- `server/main.py`: API. `POST /analyze`에 이미지를 보내면 후보 목록(분류, 글자, 위치, 기본 선택 여부, 이유)을 돌려준다
- `server/detect.py`: OCR, 끊긴 줄 조각 합치기, 규칙 후보
- `server/llm.py`: LLM 문맥 판정 프롬프트와 응답 해석
- `server/make_samples.py`: 시험용 캡처 생성(이름·번호·키는 모두 가짜)
- `extension/content.js`: 붙여넣기 가로채기, 확인 화면, 가림 처리. 데모 페이지도 이 파일을 그대로 쓴다
- `extension/background.js`: 확장 권한으로 점검 서버 호출(사이트의 CORS 제한을 피함)
- `demo/`: 데모 페이지와 샘플 이미지

## 지금 확인된 것

- 샘플 3장에서 규칙 후보가 의도대로 나온다. 진짜 키와 비밀번호는 미리 선택되고, 예시 키(`your_api_key_here`)와 예시 메일(`example.com`)은 선택이 해제된 채 표시된다
- 데모 페이지에서 확인 화면 → 가리고 붙여넣기까지 동작한다. 고른 영역만 검게 칠해지고 나머지는 그대로다
- 확장이 다시 일으킨 붙여넣기를 Lexical 편집기와 Excalidraw도 받아들인다(페이지에 스크립트를 넣어 시험)
- CPU 노트북 기준으로 OCR에 이미지 한 장당 약 2초가 걸린다

## 알려진 한계

- **OCR이 짧은 한글을 놓친다.** 표 속 이름 일부와 알림의 보낸 사람 이름을 못 읽는다. 지금은 가벼운 모바일 모델(PP-OCRv5)을 쓰고 있다
- **실제 확장으로는 아직 시험하지 않았다.** 디스코드처럼 로그인이 필요한 사이트도 아직 확인하지 않았다
- **클립보드를 직접 읽는 앱(구글 문서 등)은 막지 못한다.** 붙여넣기 이벤트를 거치지 않기 때문이다
- 드래그 앤 드롭과 파일 업로드 버튼으로 올리는 이미지는 아직 가로채지 않는다

## 다음 작업 후보

- **OCR:** 더 정확한 모델로 교체하거나, L4에서 GPU로 돌리기(`onnxruntime-gpu`와 RapidOCR의 `EngineConfig.onnxruntime.use_cuda`)
- **AI 판정:** L4에 LLM이나 VLM(화면을 직접 보는 모델)을 띄우고 프롬프트 다듬기
- **확장:** 디스코드·노션·GitHub 호환성 확인, 드래그 앤 드롭 지원
- **평가:** 정답을 표시한 캡처 100장 만들기, 규칙만 쓸 때와 AI를 더할 때의 탐지율·오탐 비교
- **서버:** 대회 서버 배포

## 외부 자원
